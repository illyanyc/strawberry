# ADR-0007: Service-to-service authentication with short-lived Ed25519 tokens

- **Status:** Accepted (provisional: default, pending research §7, §12)
- **Date:** 2026-10-17
- **Decision register:** D33
- **Related:** section 02 "Service-to-service auth"; rule SE-040

## Context

Section 02 requires that `execution` accepts intents only from authorized producers and `broker-gateway` accepts orders (and credential writes) only from specific services. Defaults offered: mTLS via a small internal CA (step-ca) or signed service tokens. All services run on one internal Docker network on one host (the Mac Mini).

## Decision

- Each service has an Ed25519 signing seed (secret `svc_<service>_ed25519`, generated by `make secrets`). Receivers mount the public keys of the callers they trust (`svc_<caller>_ed25519.pub`).
- Callers mint a token per call: claims `iss`, `aud`, `iat`, `exp` (≤ 60 s), `jti`; `v1.<claims>.<signature>`.
- gRPC: per-RPC credentials on the client, a unary interceptor on the server that verifies the token and checks the caller against a **per-method allowlist** (unlisted methods denied).
- No transport encryption between containers in Phase 0 (internal bridge network, not reachable from outside the host).

## Alternatives considered

| Option | Why not (now) |
|---|---|
| mTLS with step-ca | Strongest, adds encryption, but needs a CA container, cert rotation, and per-language TLS config; more than one host does not exist yet. Revisit in Phase 6. |
| Shared HMAC secret | Any holder can impersonate any service. |
| Network policy only | Docker bridge networks cannot express per-caller rules. |

## Consequences

- Positive: caller identity on every internal call with tiny code; keys never leave their containers; replay window ≤ 70 s.
- Negative / risks: no confidentiality on the internal network; no `jti` replay cache yet.
- Follow-up: add mTLS (or WireGuard between hosts) before services span machines.

## Validation

`TestSE040TokenVerification`; `broker-gateway` rejects calls from callers other than `api-gateway` (tested in the service).
