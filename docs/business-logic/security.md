# Security

**Prefix:** `SE-`  ·  **Owners:** `libs/go/policy`, `libs/go/audit`, `libs/go/logging`, `libs/go/secrets`, `libs/go/svcauth`, `libs/go/db`, `services/api-gateway` (auth), `services/broker-gateway` (credentials), `infra/`  ·  **Related:** [operations.md](operations.md), [ADR-0009](../adr/0009-owner-authentication.md), [ADR-0011](../adr/0011-secrets-management.md), [ADR-0006](../adr/0006-audit-log-hash-chain.md), [ADR-0007](../adr/0007-service-to-service-auth.md), [threat model](../threat-model.md) (planned)

## Scope

Owner authentication, sessions, CSRF, step-up, the authorization policy, service-to-service authentication, deploy-time secrets, broker-credential encryption, log redaction, the audit log, and database least privilege. Trading limits are in [risk-management.md](risk-management.md); step-up only guards changes to them.

## Concepts and states

- **Actor**: `owner`, `service:<name>`, `assistant`, `webhook:<name>`, or `anonymous`. Rendered this way in audit records.
- **Decision**: `allow`, `deny(reason)`, or `require_step_up`, returned by `policy.Authorize(actor, action, resource, now)`.
- **Step-up**: a fresh second factor bound to the session for `auth.step_up_window` (default 5 min). Method `passkey`, `totp`, or `recovery`.
- **Audit chain**: `hash_n = SHA-256(hash_{n-1} || canonical(event_n))`, `hash_0` = 32 zero bytes; canonical encoding in [`libs/go/audit`](../../libs/go/audit/audit.go).

## Rules

| SE-001 | Every authorization decision MUST go through `policy.Authorize`; services and the UI MUST NOT implement their own checks. | Implemented | `libs/go/policy/policy.go`; `TestSE003AuthorizeMatrix` |
| SE-002 | The action list is closed: an action not in the policy table MUST be denied for every actor. | Implemented | `libs/go/policy`; `TestSE003AuthorizeMatrix` (`made.up`) |
| SE-003 | These owner actions MUST return `require_step_up` without a fresh **passkey** step-up: `trading.live.enable`, `strategy.promote.live`, `risk.limits.raise`, `allocation.increase`, `killswitch.disable`, `broker.credentials.write/delete/status`, `mobile.order_entry.enable`, `assistant.write_tools.enable`, `data.export.positions`, `auth.passkey.delete`, and `orders.submit.manual` when the resource mode is `live`. Window: `auth.step_up_window` (default 5 min). | Implemented | `libs/go/policy`; `TestSE003AuthorizeMatrix`, `TestStepUpListCoversSection02` |
| SE-004 | Every gateway route MUST reject unauthenticated requests with 401, except the explicit public allowlist: `/healthz`, passkey login begin/finish, TOTP login, recovery-code login, first-run setup (requires a setup token), and static UI assets. | Implemented | `services/api-gateway/internal/gateway/server.go`; `TestSE004RouteInventory` |
| SE-005 | Sessions MUST be server-side: an opaque 256-bit token in an `HttpOnly`, `Secure`, `SameSite=Strict` cookie; only its SHA-256 is stored. A new session ID MUST be issued on every login. | Implemented | `services/api-gateway/internal/gateway/server.go`, `store.go`; `TestSEAuthEndToEnd`, `TestSSEStreamRequiresSessionAndEndsOnRevoke` |

| SE-009 | Exactly 10 recovery codes are generated at setup, shown once, stored as HMAC-SHA256 with the gateway key, and each is single use; regeneration invalidates all previous codes. | Implemented | `services/api-gateway/internal/gateway/auth.go`; `TestSEAuthEndToEnd` |
| SE-010 | Deploy-time secrets MUST be read only from mounted files (`/run/secrets/<name>`); never from environment variables, images, Compose files, or the repo. | Implemented | `libs/go/secrets`, `libs/py/tbcore/src/tbcore/secrets.py`; `TestGetTrimsAndRegisters`, `test_se010_get_secret` |
| SE-011 | Auth endpoints MUST be rate limited per IP and per account: after `auth.max_failures` (default 5) failures within 15 min the key is locked for 15 min, the attempt is audited, and an `alert.security` event is published. | Implemented | `services/api-gateway/internal/gateway/auth.go`, `server.go`; `TestSEAuthEndToEnd` |

## Edge cases

| Scenario | Expected behavior | Rules |
|---|---|---|
| A superuser edits an audit row with triggers disabled | `make audit-verify` fails at that sequence number | SE-020, SE-022 |
| Two services append audit events concurrently | Advisory lock serializes; chain stays linear and gapless | SE-020 |
| A log line includes an Alpaca key ID or a registered DB password | Replaced by `[REDACTED]` | SE-012 |
| Owner logged in with TOTP tries to raise a risk limit | `require_step_up` (passkey) even after a TOTP step-up | SE-003, SE-014 |
| Service token replayed 5 minutes later | Rejected as expired | SE-040 |
