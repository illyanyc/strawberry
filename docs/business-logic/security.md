# Security

**Prefix:** `SE-`  ·  **Owners:** `libs/go/policy`, `libs/go/audit`, `libs/go/logging`, `libs/go/secrets`, `libs/go/svcauth`, `libs/go/db`, `services/api-gateway` (auth), `services/broker-gateway` (credentials), `infra/`  ·  **Related:** [operations.md](operations.md), [ADR-0009](../adr/0009-owner-authentication.md), [ADR-0011](../adr/0011-secrets-management.md), [ADR-0006](../adr/0006-audit-log-hash-chain.md), [ADR-0007](../adr/0007-service-to-service-auth.md), [threat model](../threat-model.md) (planned)

## Scope

Owner authentication, sessions, CSRF, step-up, the authorization policy, service-to-service authentication, deploy-time secrets, broker-credential encryption, log redaction, the audit log, and database least privilege. Trading limits are in [risk-management.md](risk-management.md); step-up only guards changes to them.

## Concepts and states

- **Actor**: `owner`, `service:<name>`, `assistant`, `webhook:<name>`, or `anonymous`. Rendered this way in audit records.
- **Decision**: `allow`, `deny(reason)`, or `require_step_up`, returned by `policy.Authorize(actor, action, resource, now)`.
- **Step-up**: a fresh second factor bound to the session for `auth.step_up_window` (default 5 min). Method `passkey`, `totp`, or `recovery`.
- **Audit chain**: `hash_n = SHA-256(hash_{n-1} || canonical(event_n))`, `hash_0` = 32 zero bytes; canonical encoding in [`libs/go/audit`](../../libs/go/audit/audit.go).

## Edge cases

| Scenario | Expected behavior | Rules |
|---|---|---|
| A superuser edits an audit row with triggers disabled | `make audit-verify` fails at that sequence number | SE-020, SE-022 |
| Two services append audit events concurrently | Advisory lock serializes; chain stays linear and gapless | SE-020 |
| A log line includes an Alpaca key ID or a registered DB password | Replaced by `[REDACTED]` | SE-012 |
| Owner logged in with TOTP tries to raise a risk limit | `require_step_up` (passkey) even after a TOTP step-up | SE-003, SE-014 |
| Service token replayed 5 minutes later | Rejected as expired | SE-040 |
| A browser posts a subscription whose endpoint is `https://169.254.169.254/...` | 400 `bad_endpoint`; nothing stored | SE-061 |
| A push service answers 410 | The subscription is deleted; the Notifications page no longer lists it | SE-061 |
| A TradingView alert is replayed an hour later | Outside the 60 s window: 422, audited, no signal | SE-064 |
| The same alert is redelivered within a minute | 200 `duplicate`, audited, no second signal | SE-064 |
| A request reaches the UI hostname through the tunnel without Access (Bypass policy) | 403 `access_required` | SE-064 |
| The owner turns on the TradingView widget from a TOTP session | Passkey step-up required; cancel leaves it off | SE-065, SE-014 |
